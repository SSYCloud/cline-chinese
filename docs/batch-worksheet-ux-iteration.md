# Batch 工作表：Excel 式连续操作改进

状态：2026-09-28 内测反馈驱动的工作草案；以 `codex/batch-worksheet-ux` 分支实际实现和测试为准。

## 1. 问题不是 LoomLoom 要求用户点工具栏

当前工作表至少画出 31 行，但选 SkillBot 后一般只有 1 行真实 `BatchRow`。点击其余视觉空行只会选中；编辑和粘贴超出真实行会被拒绝。单击不开始输入，Enter/F2/双击打开较重的详情编辑框，Tab 又可能停在进度/输出列；每次选区变化还会排队同步宿主。因此用户感受到的是“像表格的表单”，而不是连续可录入的工作表。

LoomLoom Market API 在最终提交时接收结构化 `inputRows`。**视觉网格和键鼠手感是 Cline 客户端的责任**；只有实际输入/任务结构变更才需要宿主持久化，并在检查、报价和执行时遵守公开 schema 与费用确认。

## 2. 用户心智模型与数据边界

| 用户动作 | 即时 UI 行为 | 宿主/计费行为 |
| --- | --- | --- |
| 单击、方向键、拖选视觉空格 | 本地立即选中，可显示光标/位置 | 不创建 `BatchRow`，不改变 revision、预算或任务数 |
| 在空输入格直接键入、F2、双击 | 就地编辑，Enter/Tab 可连续录入，Esc 可撤销未提交内容 | 确认提交后才通过同一 `BatchService` 原子写入；报价失效规则不变 |
| 在视觉第 20 行输入，前面视觉行留白 | 输入仍显示在第 20 行 | 未触碰的视觉空行不进入 quote/execute；真实行需要稳定的视觉行号↔提交行序号映射 |
| 粘贴多行多列 | 先预览可写范围，按源矩形一次提交 | 整批校验、扩行和写入原子化；失败不留下半批空行；最多 100 条真实任务 |
| 点击只读状态/进度/输出格 | 可以选中和查看详情 | 不允许写入；历史/已提交/其他任务工作表仍只读 |
| 选中整行后删除（包括空白行） | 删除所选视觉行，下方行上移，选区回到邻近行 | 宿主按视觉行区间原子提交；含内容/附件须用户确认，预算失效 |
| 修改已报价输入或增删真实行 | 立即提示需重新检查和报价 | revision 变化、旧 quote 失效；不能静默运行 |

这里的“空白”分三类：**纯视觉空位**不算任务；选 SkillBot 时自动预留但始终未填的首行也不算任务；用户明确点击“新增行”创建的真实空行可以作为使用工作流默认值的任务，以支持所有公开字段可选的 SkillBot。检查表必须把后者标为 **“使用默认值”**，同时显示最终将提交的真实任务数，让用户在付费前确认。

## 3. P0 连续录入契约

1. 单击选中当前格；可打印字符直接以新值开启格内编辑，F2/双击编辑原值。大段代码/文本仍可打开完整详情编辑器，不能让长内容困在一行高的输入框中。[Excel 官方快捷键](https://support.microsoft.com/en-us/accessibility/excel/keyboard-shortcuts-in-excel)是手感参照，不意味着实现完整 Excel。
2. Enter 提交并向下一视觉行移动，Shift+Enter 向上；Tab 移到下一个可写的公开输入字段，末列换到下一视觉行首个输入字段，Shift+Tab 反向；Esc 放弃本地草稿。asset 字段仍走可信文件选择/上传，模型字段用允许的列表，不变成随意字符串。
3. 从任意当前可编辑空位写入后保留其视觉位置；UI 显示的行号、`BatchRow.id`、LoomLoom 的 `sourceRowIndex`、历史结果和本地产物必须可复原对应。不能把视觉第 20 行写入后悄悄挪到第 2 行，也不能在中间制造 18 条付费空任务。
4. 粘贴含换行/Tab 的矩形文本时，仅可覆盖公开输入列；超出范围、含只读列、无效枚举/模型或超过上限要整批拒绝并说明位置。一次有效粘贴只产生一次 revision/持久化；不应先 `addRows` 成功再 `patch` 失败。
5. 选区和正在编辑的草稿先由 Webview 即时呈现；高频选区同步可去抖/latest-wins，但真正写入仍待宿主确认。宿主拒绝时恢复权威值，保留用户草稿供修正，不悄悄覆盖另一端 Agent 的更新。
6. 连续按 Enter/Tab 不能被上一格的宿主响应阻塞：本地可继续输入，后台按顺序提交并用每笔成功响应的 revision 做下一笔 CAS。若某笔遇到 Agent 并发改动、断网或持久化失败，停止后续自动写入并保留每格地址和值供用户核对；检查/报价/运行在未解决的排队输入前必须禁用。
7. 右侧有未保存的格内/公式栏草稿或待确认写入时，宿主记录该工作表实例的编辑租约。左侧聊天与右侧工作表的检查、报价、运行统一由宿主拒绝，不能仅把右侧按钮置灰；保存成功、明确放弃或关闭整张工作表后释放。付费前还要直接询问打开的表格页，覆盖首字输入到租约消息到达之间的间隙；隐藏页无法确认时拒绝报价/运行，并提示重新打开或关闭工作表，不能把隐藏当成放弃草稿。

## 4. P1 补齐的表格习惯

- 鼠标按住拖出矩形选区；行头右键插入与键盘快捷键；有内容的行删除保留明确确认。工具栏选中整行删除的下移语义属于 P0。
- Ctrl/Cmd+C/V 的选区复制、整块粘贴，以及清除选区；填充柄只有实现复制/填充且有覆盖确认时才显示，否则移除当前仅装饰的蓝色块。
- 单元格格式、查找和缩放继续使用 VS Code 深色主题变量；无需实现 Excel 公式引擎或 `.xlsx` 文件导入。
- 输入历史较大时，视图状态不应因每次点击都全量克隆并序列化运行历史；对选择事件做合并，对输入和运行事件保留可靠同步。

## 5. 核心验收场景

| ID | 操作 | 期望 |
| --- | --- | --- |
| UX-01 | 选首个空白输入格，直接键入后 Enter | 格内值保存并下移；无需先点“新增行/编辑单元格” |
| UX-02 | 在最后一个可写字段按 Tab | 跳到下一视觉行第一个可写字段，不落在进度或输出列 |
| UX-03 | 双击已有长文本、按 Esc | 进入编辑但不改权威值、不使预算失效 |
| UX-04 | 在视觉第 20 行键入，2～19 留白 | 值留在第 20 行；检查/报价只计算真实任务，不产生 18 条隐形任务 |
| UX-04a | 首行仅由选择 SkillBot 自动预留且未填，另一处视觉空行有内容 | 未填的预留首行不参与检查/报价，也不阻止其他真实行提交 |
| UX-04b | 用户明确点击“新增行”但字段全留空 | 检查表标注“使用默认值”，将它作为一条任务计入预算；仍需用户确认费用 |
| UX-05 | 从第 2 行粘贴 3×2 文本 | 原子写入对应可写字段和所需真实行；一次 revision；表格与聊天同步 |
| UX-06 | 粘贴第 101 条或跨入输出列 | 整批失败，原输入与预算保持原样，并指出原因 |
| UX-07 | 报价后修改一格或删除真实行 | 旧预算立即失效；必须重新检查、报价和明确确认 |
| UX-08 | Agent 同时编辑当前任务，用户保存旧草稿 | revision 冲突可见，保留用户未提交内容供选择；不覆盖 Agent 新值 |
| UX-09 | 查看历史表、已提交批次或另一任务面板 | 可选中/复制/查看，不能误写到当前任务或自动扩行 |
| UX-10 | 批量运行后查看视觉稀疏行的状态/产物 | `sourceRowIndex` 正确回到原视觉行，文件仍保存在原任务工作区 |
| UX-11 | 连续在两格按 Enter，第一格尚未收到宿主响应 | 第二格可立即输入；提交队列用第一笔 ACK 的新 revision；两格最终都在聊天/表格出现 |
| UX-12 | 队列第一笔与 Agent 修改冲突或断网 | 不自动继续后续写入；失败与未发送草稿保留并标出格地址，用户核对后可重试 |
| UX-13 | 右表尚有未保存草稿，左侧点击报价/运行 | 宿主拒绝旧输入付费操作并提示先保存或放弃草稿；隐藏右表仍拒绝，关闭工作表释放 |
| UX-14 | 选中空白视觉第 3 行删除，已有真实第 20 行 | 第 20 行移动至第 19 行；不触发任何新任务，含真实内容的删除要求确认 |

自动化测试不调用真实付费接口。真机验收再使用获授权的低费用测试账号，先核对服务端预算并由测试人员确认后运行。

## 6. 实现切分与非目标

- Webview：即时选区、格内草稿、键盘/鼠标、可见空白行与粘贴预览；不独自决定付费输入。
- 扩展宿主：稀疏行持久化、原子写入与 CAS revision、公开字段校验、quote 失效、提交行↔视觉行/产物映射。右侧工作表和左侧 Cline Agent 仍读写同一个任务状态。
- 非目标：让任意空白点击直接创建真实任务、在输入中自动执行、把本地表格做成完整 Excel、通过前端推算 LoomLoom 隐藏步骤进度。

先完成 P0 并请内测者实际用键盘连续录入一批，再决定 P1 的细节优先级；“看起来像 Excel”不能替代“真实编辑流畅且不会产生意外付费任务”。

## 7. 内测补充：填完后的主操作必须比编辑工具更醒目

标题下、可横向滚动的表格工具栏之外，固定显示本批的单一主操作。按同一宿主状态机依次呈现：检查输入 → 确认输入并查看预算 → 显示服务端报价与币种后由用户确认并运行。零条任务时保留禁用的“检查输入”和填写提示；预算失效时绝不显示可用的运行按钮；运行中只显示状态，不允许重复提交；历史表只读。窄窗口要让主按钮始终可见，不能随字号、冻结列等次级工具一起横向滚走。左侧 Batch 对话保留同样的操作能力，两端不得维护两份输入或两套付费状态。

模型输入只读取 SkillBot 的公开字段与 LoomLoom 当前支持列表。像“文本模型（留空用默认）”这样的标签，可剥离末尾说明后识别为明确的文本模型字段；泛用字段名 `modelChoice` 本身不能推断模型类型，显式禁止覆盖的 SkillBot 仍只能使用其推荐默认模型。

## 8. 结果交付目录与媒体预览

- 新批次的默认交付根目录是该 Cline 会话所属的 VS Code 项目工作区，不是 SDK 为无项目聊天创建的内部 `workspaces/chat`。默认文件放在项目的 `.cline/loomloom-outputs` 下，按任务、运行和行分目录；多根工作区优先原会话项目，新会话可按当前活动文件归属选根。没有可确认的项目目录时，付费执行前必须通过 VS Code 原生目录选择框明确指定。
- “更改后续位置”只改变未来运行的默认目录；`execute` 创建运行时冻结交付目录。已执行运行需要用户单独点“另存本批”选择目录；重新导出不会删除原文件，也不会把另一个会话或今天活动编辑器的目录偷偷借给旧运行。自选目录是精确根目录，目录下仍按任务/运行/行组织文件。
- 文本、图片与视频的本地保存状态应分别可见；媒体失败不改变云端运行成功状态。图片/视频从当前任务的 run/行/产物索引重新定位，宿主仅下载公网 HTTPS 媒体，不转发胜算云凭据、不跟随重定向，校验 MIME 和文件头，设单文件及每批体积上限，原子保存且不覆盖已有文件。
- 工作表媒体单元格提供“预览”入口。图片/视频只使用宿主验证后的本地 Webview URI，在暗色详情框惰性加载；视频不自动播放，关闭详情即停止；加载失败显示重试和外部打开兜底。签名 `accessUrl` 不新增进入 Webview 草稿或日志，也不直接作为 Webview 预览来源。现有运行结果快照仍会保存服务端返回的 `accessUrl`；后续需设计签名 URL 脱敏与使用前刷新，不能本轮直接删掉导致历史结果不可重试。
